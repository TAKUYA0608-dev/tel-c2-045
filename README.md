# TEL-C2-045 — Telecom Network Firmware Change Window Risk Brief Agent

> **Category**: Cat 2 (domain workflow (a job to be done))
> **Industry**: Telecom

## Overview

Given a firmware change package — change id, change plan, target assets, the maintenance window, the rollback plan and customer-impact criteria — the agent drafts a risk brief for change approval: it classifies each asset's criticality tier and downstream dependencies from a shipped network-element reference, scores rollback completeness, dependency coupling, blast radius, customer impact and window validity with a fixed rubric into severity-tagged findings, structures the risk factors, rollback assessment and recommended conditions into a cited brief, and routes material decisions and uncertainty to the change advisory board with candidate owners only. Scoring is a deterministic rubric — no LLM is used. The brief is never an approval decision; credentials, My Number values, phone numbers, e-mail addresses and names are redacted at intake and on output, a package with no assets gets an out-of-scope brief, and every brief is marked DRAFT. The asset-tier reference shipped here is a small seeded sample — replace it with your own network inventory.

This is an agent template built with the **AGENTIC STAR** development platform and the
**AgentCore Framework**. It is intended to be taken as a starting point: fork it, adapt it to
your own data and policies, and run it inside your own AGENTIC STAR deployment.

## Requirements

**This template does not run standalone.** It requires:

| Requirement | Notes |
|---|---|
| **AGENTIC STAR platform** | The agent connects to the platform at start-up. Without it, start-up fails immediately (see *Behaviour without the platform* below). Deployment guides and API documentation: [AGENTIC STAR Developers](https://developers.fd.agenticstar.tm.softbank.jp/) |
| **AgentCore Framework** (`agenticstar-agentcore`) | Installed from PyPI as a dependency. |
| Python | 3.11 or later (`requires-python = ">=3.11"`) |

```bash
pip install -e .
```

### Behaviour without the platform

The framework is designed to run **only** on AGENTIC STAR. There is no fallback or degraded
mode. If the platform is unreachable or the SDK version does not match, the agent raises
`PlatformRequired` during graph compile / start-up preflight rather than starting in a partially
working state. This is intentional — a half-running agent is worse than one that refuses to start.

## Quick Start

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
python -m pytest tests/ -v
```

Tests run without a platform connection. Running the agent itself does not.


## Customising

1. Adjust `config/` for your own environment and policies.
2. Replace the knowledge sources and sample data with your own.
3. Review the node implementations under `src/nodes/` for domain-specific logic.
4. Re-run the test suite.
